# Security Policy

## Supported versions

Security fixes are evaluated for the current release line. Earlier tagged releases are retained for historical reproducibility and are not actively maintained.

## Reporting a vulnerability

After the repository is public, use GitHub private vulnerability reporting to report a suspected security issue. Do not include exploit details, credentials, private data, or proof-of-concept material in a public issue.

If private vulnerability reporting is temporarily unavailable, do not disclose sensitive vulnerability details publicly.

## Scope

Security reports should concern the software, packaged distributions, command-line interface, loopback browser application, dependencies, or repository configuration.

Data-quality findings and scientific or clinical interpretation are outside this security-reporting process.
